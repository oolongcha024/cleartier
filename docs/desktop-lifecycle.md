# 后台运行、恢复与诊断

阶段 7 按已确认方案实现，当前交付以 Windows 为先。本地编译与自动化检查不能替代 Windows 托盘、UAC、登录启动、驱动、休眠及安装实机验收。macOS、Linux 保留共用实现；它们的权限、桌面环境与安装支持分别验收，非 Windows 自动 TUN 提权仍未实现。

## 窗口与退出

- 默认点击窗口关闭按钮隐藏到托盘，保留 WebView、配置草稿与所有连接。首次关闭说明行为，选择后台运行后记住说明已读。
- 托盘使用应用图标，左键打开窗口，菜单提供“打开 ClearTier”和“退出 ClearTier”。设置可将关闭行为改为退出。
- 托盘创建失败时保持窗口可见，关闭按退出处理，避免隐藏后没有返回入口。
- 同一用户会话中重复打开应用只唤起已有窗口；核心工作进程与分项检查先于单实例插件分派，不受 GUI 单实例限制。
- 明确退出时，有运行中的实例或待恢复连接则先确认。确认后阻止新的连接操作、取消恢复任务、关闭核心并等待清理；失败保持窗口可用并提示再次退出。未运行网络时直接清理退出。
- 界面进程异常结束时沿用管道 EOF／控制端存活监控清理核心。第一版不提供独立于 GUI 常驻的系统服务。

## 登录启动与设置

后台偏好保存于 Tauri `app_config_dir()/desktop.json`，与含凭据的 `networks.json` 分开。保存使用临时文件原子替换，保留未知字段；损坏或较新版本不被默认值覆盖。读取失败显示错误，修复文件后可刷新。初次读取失败暂停自动恢复。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 关闭窗口时 | 后台运行 | 可改为退出客户端 |
| 登录系统后启动 | 关闭 | 当前用户登录后启动并进入托盘；不在登录前组网 |
| 连接异常后自动恢复 | 开启 | 只恢复本次 GUI 会话中原本成功运行的网络 |

Windows 登录启动通过 `auto-launch` 明确指定 `CurrentUser`，启动项名称为 `ClearTier`，命令行是带引号的当前可执行文件路径及 `--background`。不写系统级启动项，不提升 GUI 权限。设置读取实际系统启动状态；系统项更新后配置落盘失败，会尝试回滚系统项并重新读取，避免错误显示保存成功。macOS、Linux 使用 Tauri autostart 插件，仍待平台验收。

逐网络的自动连接与上述设置独立，继续使用阶段 3 的一次性启动队列。打开窗口不重新执行队列；新打开 GUI 时才执行。取消 UAC 后停止本次队列，保留开关。免安装包启用登录启动后应保留所在目录；移动程序后应重新关闭、开启该设置以更新路径。

## 恢复策略

恢复由普通权限 Rust GUI 进程中的每秒任务调度，使用跳过遗漏 tick 的策略；每个网络的恢复任务独立执行，采样和其他网络操作不等待其就绪。手动断开、关闭恢复或退出使旧代次失效；已发出的启动必须完成通信，并清理迟到实例后才确认停止。不依赖隐藏窗口里的 JavaScript 计时器。

| 情况 | 处理 |
| --- | --- |
| 核心运行、暂时没有节点／入口不可达 | 由 EasyTier 自身恢复连接，客户端不重启实例 |
| 仅查询失败或快照未知 | 保持未知与过期信息，不据此启动第二个实例 |
| 已运行的实例消失或可恢复的实例／核心异常 | 按 2、5、15 秒退避，最多重试 3 次 |
| 连续短时间崩溃 | 共用上述预算；连续稳定运行 60 秒后才重置预算 |
| 重新启动需要提权 | 停止恢复并提示手动重新连接，不弹出后台 UAC |
| 配置、地址／网卡冲突、资源或身份校验问题 | 停止重试，显示实际错误，等待处理 |
| 主动断开／明确退出 | 先取消恢复意图，保持断开 |
| 新参数主动应用失败 | 保留失败结果，不恢复旧连接、不自动重试应用 |

恢复只使用断线前的运行参数，不读取已保存的新参数，不写配置、不消除待应用修改。用户主动重连使用已保存参数。关闭自动恢复会取消等待任务；重新开启只跟踪当时仍然运行的实例，不启动已经断开的网络。

恢复意图及预算仅存在于当前 GUI 内存中。客户端重新启动后只遵循逐网络自动连接偏好，不恢复上次退出前的临时意图。界面通过快照展示等待、达到上限、需要授权及需要处理的状态；等待时可主动断开，失败后可手动重新连接。

## 诊断与隐私

设置中的诊断卡片提供本地配置可读性、核心状态与运行实例摘要，展示最近 5 条错误，并提供打开日志目录、刷新和导出入口。不增加独立诊断页面，不进行公网测速，也不自动修改网络配置。

诊断导出是通过系统保存对话框选择位置的 JSON 文件。字段采用白名单生成，包含应用／核心版本、平台和架构、配置是否可读、核心状态、匿名编号的实例状态、是否取得虚拟地址、预期及实际 TUN 存在状态、节点数量、恢复状态、错误码与必要进程事件。TUN 检查使用系统接口查询，不请求提权、不创建网卡，显式 `no_tun` 配置不被误判为缺少网卡。原始日志不直接复制进导出文件。

排除网络名称、密钥、服务器地址、节点名称、具体 IP、网络 UUID、用户目录、完整 TOML、邀请原文和底层自由文本错误；不自动上传。错误历史在当前会话中最多保留 50 条，导出同时合并已有进程日志中的错误码。进程日志仍按约 512 KiB 轮换并保留上一份，诊断最多读取两份各 1 MiB、保留最近 200 条允许的进程事件。

浏览器预览仅模拟后台设置，使用独立的本地预览记录，不修改系统启动项。日志及真实文件导出明确提示需要桌面客户端。

## 安装、升级与卸载

Windows NSIS 明确使用当前用户安装。复用 Tauri 原生模板中默认未选中的“删除应用数据”选项：安装与升级保留配置；正常卸载默认保留配置，只有明确勾选才删除应用配置和本地数据。卸载清除登录启动项；更新模式保留启动项。

安装／卸载 hook 检测现有单实例入口，说明连接将断开，通知原 GUI 通过 `--installer-shutdown` 清理，并最多等待 25 秒。无法确认退出就中止，不继续覆盖仍在使用的程序。该参数只处理退出，不启动连接或提升权限。没有运行实例时不创建额外 GUI。

早于阶段 7、没有单实例通知入口的旧测试版本应先手动退出，再安装；它们无法处理新的通知参数。驱动行为和升级期间的资源清理仍需 Windows 实机验证，不会主动删除其他软件共用的驱动服务。

| Module | 职责 |
| --- | --- |
| `src-tauri/src/desktop/` | 托盘、窗口请求、退出清理、启动设置与原生诊断文件操作 |
