# 第一版需求基线

确认日期：2026-11-07。

状态：用户已确认，以本文作为第一版可交互原型的需求基线。界面布局、视觉风格及具体操作形式尚未确定。本文的验收场景用于表达已确认需求，具体测试方法随实现确定。

## 1. 产品定位与目标

开发一个基于 EasyTier 核心的本地桌面客户端，面向以下场景：

- 异地组网：连接不同地点的个人设备、家庭设备或服务器。
- 远程办公：保持办公网络连接，查看设备和连接情况，帮助排查访问问题。
- 游戏联机：方便地邀请朋友加入网络，查看直连／中转情况及延迟等信息。

主要改善方向：

1. 提升官方 GUI 的视觉体验和交互清晰度。
2. 简化已部署服务器场景下的配置、验证和分享流程。
3. 让受邀者能够方便地加入网络并判断当前连接情况，减少创建者逐项指导的成本。
4. 保持与 EasyTier 生态的开放性，支持官方配置迁移。

上述场景都在目标范围内，尚未为它们设定优先级。

### 界面设计规范

用户已明确要求采用 Material Design 3。不同原型方案应遵循同一套设计规范，通过布局与信息层级探索差异，而不是更换设计体系。具体配色、视觉细节和页面布局仍需通过原型验证。

第一轮原型后，用户选择 A 的导航抽屉方向，并要求首页改为仪表盘、提供快捷操作，以网络下拉框替代三栏结构中的独立网络列表；详细配置分页面管理。具体实现仍在原型中验证，见[原型方向记录](prototype-design.md)。

## 2. 用户与使用前提

用户可以具备一定的 IP、端口、协议和密钥知识，但日常连接不应要求反复填写已有信息。

创建和分享网络的用户，与收到邀请后加入网络的用户，具有不同的操作任务。界面需要兼顾这两条流程，不预设所有受邀者都熟悉底层参数。

服务器已经部署好 EasyTier。客户端负责配置连接信息、验证连接及后续管理，不负责通过 SSH 等方式部署、升级或运维服务器。

## 3. 平台、核心与语言

| 项目 | 已确认要求 |
| --- | --- |
| 桌面平台 | Windows、macOS、Linux |
| 平台支持含义 | 包含安装、连接、后台运行等实际适配与验证，共用代码不能替代平台验证 |
| 移动端 | 第一版不包含 Android、iOS |
| 核心分发 | 安装包内置经过验证的兼容 EasyTier 核心，无需另装官方客户端或手动指定核心路径 |
| 核心版本 | 第一版不提供任意切换核心版本的功能 |
| 语言 | 中文优先，保留国际化能力；英文完整翻译可后续补齐 |

依赖准备阶段保留 Tauri 2，用户明确选择 React。当前采用 React、TypeScript、Vite，交互底座使用 Base UI，后续按 MD3 实现样式，配合 Material Color Utilities 和 Material Symbols。组件库、色彩工具的安装不等于已完成 MD3 组件实现。EasyTier 核心集成方式及平台开发与验证顺序仍待定。

## 4. 网络创建、加入与管理

### 4.1 操作入口

提供以下能力，具体入口位置、引导步骤和布局通过原型确定：

- 粘贴邀请加入网络。
- 手动填写信息加入网络。
- 创建网络并分享。

“创建网络”指基于已部署服务器配置网络名称、加入凭据等信息，不包含部署服务器。

### 4.2 多网络

- 支持保存多个网络。
- 支持同时连接多个网络，例如保持办公网络连接的同时加入游戏网络。
- 每个网络单独展示状态，并提供连接、断开及配置操作。
- 地址、端口等冲突需要提供明确反馈，避免仅显示笼统的连接失败。
- 支持本地备注名，例如“公司办公”“周末联机”。备注与实际组网使用的网络名称分开保存。
- 修改本地备注只影响本机展示，不触发组网实例重建。

### 4.3 信息展示

采用简洁操作配合可展开详情的方向，不删除技术配置能力：

- 邀请解析后，提供加入预览，展示网络名称、服务器地址等信息。
- 用户可以进一步查看、修改相关连接参数。
- 密钥默认遮罩，允许主动查看。
- 保留手动配置入口。

具体哪些字段默认可见、如何展开、在哪一步编辑，留待原型验证。

## 5. 邀请与配置兼容

### 5.1 第一版邀请流程

1. 创建者配置网络、验证连接。
2. 客户端生成可复制的邀请内容。
3. 创建者通过聊天软件等现有渠道发送。
4. 接收者在客户端粘贴邀请，查看解析结果。
5. 接收者确认加入并查看连接情况。

邀请可以携带建议展示名称，接收者可以修改本地备注。

第一版以复制、粘贴邀请为主要方式，不依赖独立分享网站或聊天软件识别自定义链接。邀请编码、字段结构和版本格式尚未确定。

### 5.2 凭据边界

- 第一版分享现有网络的加入凭据。
- 明确提示邀请包含加入凭据，接收者可能继续转发。
- 不承诺独立撤销某份邀请、限制使用次数或强制过期。
- 若后续需要上述能力，应结合服务端实际支持另行设计。

### 5.3 官方客户端兼容与迁移

- 支持导入官方 TOML 配置。
- 支持导出可供官方客户端使用的标准配置。
- 完整便捷的邀请解析体验以双方使用本客户端为前提；官方客户端用户可以使用标准配置。
- 本地备注、界面偏好等应用信息与组网配置分开保存。
- 尽可能保留界面暂未覆盖的配置项。
- 无法完整处理某些配置时明确提示，避免编辑和保存后静默丢失字段。

文件邀请、二维码、点击链接唤起客户端等形式不属于第一版必须实现的范围。

## 6. 后台、启动与恢复

- 默认关闭窗口后继续在后台保持连接。
- 用户可以通过系统托盘或菜单栏重新打开窗口。
- 第一次关闭窗口时解释后台行为，并允许在设置中调整。
- “退出客户端”作为单独操作，操作前明确说明对现有连接的影响。
- “开机启动客户端”与“某个网络自动连接”分开设置。
- 新加入网络默认手动连接，用户可以逐个启用自动连接。
- 运行中意外断线自动尝试恢复。
- 用户主动断开的网络保持断开，不自动重连。

退出时核心／服务的最终生命周期、各系统后台实现和自动重连策略等细节，后续结合实现与原型明确。

## 7. 状态、设备与诊断

### 7.1 状态依据

- 以 EasyTier 实际提供的运行信息、节点、连接事件及错误为依据。
- 不预先假设核心提供某套完整状态机。
- 区分核心运行、节点连接和目标应用可访问这几个不同事实。
- 不能仅依据 `running` 标记就显示“组网成功”。
- 查询失败、无法取得实例信息与用户主动断开需要区分。
- 单个连接错误不自动等同于整个网络不可用。
- 前端推导的状态和原因需要与核心直接提供的信息区分。

状态文案、展示层级、流转映射及刷新策略在原型与接口适配阶段明确。具体源码依据见[官方项目调查](upstream-research.md)。

### 7.2 设备基础操作

- 查看设备信息。
- 复制虚拟 IP。
- 查看连接详情，包括核心能够提供的直连／中转、协议、延迟、丢包等信息。
- 由用户主动触发基础连通性检查。

第一版不包含远程桌面、SSH、共享文件夹的快捷启动及游戏启动器集成。

### 7.3 诊断

- 提供连接指标与近期错误。
- 支持复制、导出诊断信息。
- 导出的诊断信息默认去除密钥等敏感内容。
- 区分测量结果与推测原因。
- 帮助用户区分实例启动、节点连接和目标服务访问等不同层面的问题。

第一版不包含带宽测速及自动修改网络参数。基础连通性检查使用的具体探测方式尚未确定。

## 8. 配置编辑与生效

- 支持先保存修改、稍后应用，也支持立即应用。
- 明确标记尚未应用的修改，避免用户误判当前运行配置。
- 涉及重连时，在操作前明确说明影响哪个网络。
- 应用某个网络的修改时，其他网络应继续保持连接。
- 本地备注等纯客户端设置直接保存，不触发核心实例重建。

示例：办公网络正在传文件，用户修改服务器地址后，可以先保存，等方便时再重连应用；也可以立即应用，并获知该网络将重建连接。

此处确认的是行为要求，不预先规定必须采用两个按钮。配置保存位置、草稿与运行配置的数据模型、可热更新字段等，需要结合核心接口另行设计。

## 9. 第一版范围之外

- 服务器自动部署、升级和运维。
- 移动端客户端。
- 独立邀请撤销、限次和过期机制。
- 文件邀请、二维码和链接唤起的完整体验。
- 远程桌面、SSH、共享文件夹及游戏启动器集成。
- 带宽测速、自动修改网络参数和专门的游戏调优功能。
- 任意切换 EasyTier 核心版本。
- 对所有高级能力提供完整的可视化配置。

子网代理、ACL、复杂路由等高级配置的可视化范围按实际需要确定；第一版保留高级配置入口和 TOML 导入导出能力。

## 10. 原型范围与验收场景

下一阶段先制作使用模拟数据的可交互原型，暂不接入真实 EasyTier 核心。原型中的连接、诊断和指标均为模拟，不代表已实现真实功能。

### 场景 A：创建并分享

用户能够配置一个基于已部署服务器的网络，查看验证反馈，复制邀请；能够理解邀请包含加入凭据，并找到标准配置导出能力。

### 场景 B：收到邀请后加入

用户能够粘贴邀请，检查解析结果，修改本地备注，确认加入，并查看设备及连接情况。流程应覆盖无效邀请及连接失败的反馈。

### 场景 C：多网络日常管理与诊断

用户能够同时管理办公和游戏网络，分别连接、断开，查看设备、连接详情与错误，使用基础诊断入口，并理解主动断开与意外断线的差别。

### 场景 D：编辑与后台行为

用户能够理解尚未应用的修改、应用后的重连影响，以及关闭窗口后继续连接的行为；能够分别设置客户端开机启动和各网络自动连接。

原型优先验证 A、B、C 三条主流程，D 用于补充验证已确认的行为约定。

## 11. 仍需验证或决定的事项

- 正式项目名称，以及 Material Design 3 规范下的具体配色与视觉细节。
- 页面布局、导航、表单展开方式和按钮安排。
- 各桌面平台开发与验证的先后顺序。
- Tauri 桌面工程配置、MD3 组件实现及 EasyTier 核心集成方式。
- 邀请的具体编码、字段、版本及解析规则。
- 核心状态到界面文案的映射与刷新机制。
- 核心退出与后台服务生命周期。
- 配置持久化、草稿和运行配置的一致性实现。
- 基础连通性检查方式与诊断脱敏细节。
- 高级配置可视化范围，以及未覆盖配置项的保留方式。

以上事项不应被视为已确认的产品决策。后续通过原型、源码核查或单独讨论推进。
