# 网络配置存储

本文描述阶段 2 的配置存储。阶段 3 已接入真实连接、重连、立即应用及自动连接；行为见[连接管理](connection-management.md)。现有字段已映射到核心；阶段 5 已接入高级兼容校验及官方 TOML 导入导出，见[官方 TOML 兼容与高级配置](official-toml.md)。

## 使用规则

- 仪表盘和网络配置页均可手动添加网络，复用编辑对话框。新记录分配 UUID，默认手动连接，保存后成为选中项。
- 网络名称和密钥保持原样，不因界面编辑去除首尾空格；密钥可以为空。本地名称留空时使用网络名称。
- 同一网络允许保存多套配置。相同名称和密钥会提示已有记录，仍可明确选择另存；每条记录具有独立 ID 和默认 TUN 名称。
- 备注、图标、自动连接偏好属于客户端信息，与连接参数分开保存。自动连接开关保存偏好，由阶段 3 在应用启动时执行。
- 删除前确认，仅删除本机配置；运行中、状态未知或仍占用运行资源的记录不能直接删除，需先断开。启动失败且已释放资源的配置可以删除。
- 未保存的编辑在关闭时询问是否放弃，不自动持久保存未确认的草稿。
- 重新打开客户端时恢复上次选择；选中项不存在时选择第一条，没有网络时显示添加入口。

## 结构与接口

`src-tauri/crates/cleartier-config` 是独立存储 Module，不依赖 Tauri 或 EasyTier。其 Interface 为 `load / save / restore`，隐藏文件格式校验、原子替换、备份、锁与冲突处理。

Tauri 的 `config_load / config_save / config_restore` 委托该 Module。前端 `platform/configuration.ts` 提供桌面 Adapter，`features/networks/network-store.ts` 串行处理持久修改，只有写入成功才更新已保存状态。`persistence.ts` 负责持久数据和展示状态之间的转换。

设备图标偏好保存在 `client.peerIcons`，以对端配置实例 UUID 为键，不进入核心连接配置；缺失该字段的现有 v1 文件按空偏好读取。保存与恢复自动均通过同一原子写入流程。

浏览器预览使用独立的内存数据和演示运行 Adapter，不访问桌面配置，也不在原生命令失败后切回演示成功。

## 目录与格式

配置放在 Tauri `app_config_dir()` 返回的应用目录中，由当前普通用户读写。Windows、macOS、Linux 的实际基础路径遵循各自系统规则，不在代码中硬编码账户或目录。安装版及免安装测试版使用相同规则，移动 exe 不移动用户数据。

| 文件 | 内容 |
| --- | --- |
| `networks.json` | 当前已保存配置 |
| `networks.backup.json` | 上一次成功保存前的配置 |
| `networks.lock` | 多进程协调写入的稳定锁文件 |
| `networks.damaged-<UUID>.json` | 用户确认恢复时保留的异常原件 |

文档使用 JSON v1，包含 `version`、`revision`、`selectedId` 和 `networks`。每条网络包含 `id`、`client` 和 `config`；`client` 保存 `alias / icon / autoConnect / peerIcons`，`config` 保存现有表单的连接字段。

客户端信息与连接字段在同一文档中分组，保证一次保存能原子提交；不将多文件更新视作单次原子操作。文档、记录、客户端信息和配置均保留未知字段。该保证针对存储格式。阶段 5 使用可选 `config.officialToml` 保存导入底稿，另以表单字段表达修改；导出只覆盖修改部分，保留未展示内容，不保证 TOML 注释与排版。

目前没有旧的真实配置格式需要迁移，演示数据不自动迁移到用户配置。后续变更需要明确的版本迁移；不兼容版本会被拒绝读取和写入，避免旧客户端覆盖新格式。

按用户确认的方案，配置、备份和异常原件均可能包含明文密钥及服务器凭据。界面默认遮罩，存储错误只返回错误类别，日志不写配置正文；没有额外主密码、凭据库或静态加密承诺。

## 保存、加载与失败

保存前校验已知结构、实例 ID、服务器地址及参数格式；连接可达性不属于格式校验。文件限制为 4 MiB。

每次读写取得独立锁文件的排他锁。保存需要匹配调用方读到的修订号，冲突时拒绝覆盖并提示重新加载。数据先写入同目录临时文件并同步，再原子替换目标文件；正常保存只从已校验的当前文件更新备份。

首次启动仅在当前文件和备份均不存在时返回空列表。损坏、版本不兼容、超限、目录不可读写均显示实际类别，不把错误当作空配置，也不自动覆盖。显式恢复先保留异常原件，再用有效备份替换当前文件；不自动恢复或重置。

启动后查询当前核心快照，该查询不启动或提权核心。文件中不保存运行状态、设备、流量或运行参数快照；查询失败显示状态未知，不能由已保存配置推断正在连接。

## 验证与 Windows 验收

独立存储测试无需安装桌面系统开发库：

```bash
cargo test --locked --manifest-path src-tauri/Cargo.toml -p cleartier-config
pnpm test
pnpm build
```

Windows 构建入口会先运行存储测试，再生成所选产物。当前本地结果不能替代新产物的 Windows 实机验收：

1. 新用户数据目录首次打开时无演示网络，可以添加自己的配置。
2. 添加两套配置，修改备注、图标、高级参数与自动连接偏好，切换选中项；退出重开后均保留，连接状态由核心重新同步，只有启用自动连接的网络才尝试连接；首次需要 TUN 时仅核心请求 UAC。
3. 添加同名同密钥网络，确认提示后另存，检查默认 TUN 名称不同。
4. 编辑后取消，确认能继续编辑或放弃；删除前确认，删完最后一条显示添加入口。
5. 使用测试数据确认保存失败保留输入、重新加载能读取磁盘结果；不要通过损坏日常配置来测试。
6. 使用备份副本测试配置损坏及显式恢复，确认异常原件保留。两个客户端窗口修改同一份数据时应显示冲突，不静默覆盖。

以上步骤不要求真实服务器可达，不验证实际组网、驱动或设备间通信。
