# 测试与验收

自动化检查和实机验收分别记录。Windows 早期核心分项检查已有通过记录，当前完整功能仍待同一新产物的集中验收；macOS、Linux 的安装、权限、连接及后台行为待各自验证。

## 自动化覆盖边界

| 检查             | 覆盖                                                                                   | 不代表                                  |
| ---------------- | -------------------------------------------------------------------------------------- | --------------------------------------- |
| 前端与脚本测试   | 配置工作流、并发与失败、邀请、遥测、版本推进及更新状态及模拟 GitHub API 的草稿发布流程 | 原生系统行为和真实 Release 上传已验证   |
| Rust 测试        | 存储、TOML、调度、更新间隔／渠道／签名、进程通信与部分真实无 TUN 网络                  | Windows 驱动及完整 GUI 行为已验证       |
| 浏览器回归       | 共享模拟 Adapter 下的交互、布局、错误反馈及场景切换                                    | 真实剪贴板、文件对话框或系统网卡已验证  |
| Windows 构建检查 | ZIP／NSIS 编译、图标资源、Direct／Process／Recovery／MissingResource                   | UAC、真实 TUN、双机通信及长期运行已验证 |

执行命令见[开发指南](development.md#自动化检查)。`tests/fixtures/network-contract.json` 同时约束前端消费、Rust 存储及快照序列化；开发面板与场景模拟仅由开发入口加载；生产构建检查拒绝打入 `dev/` 或 `tests/` 模块。浏览器测试直接操作同一模拟 Adapter，不再伪造 Tauri 全局对象。

## 实机准备

使用同次成功构建的完整 ZIP 和 NSIS，从对应的 `windows-diagnostics-*` Artifact 获取 `build-info.json` 核对版本、提交及校验值。先退出旧版本，备份测试配置；两种分发形式共用用户数据目录，不同时运行。准备两个不冲突的测试网络和另一台设备，邀请解析需另一份 ClearTier。

以下为可重复执行的验收模板。每个候选版本复制清单到对应 Issue 或发布记录，未执行项目保持待验收；不要用历史包的通过结果替代当前提交。

## 配置与连接

- [ ] 新数据目录为空；添加、编辑、删除、网络／设备图标、最后选择及自动连接偏好在明确退出重开后保留，新网络默认手动连接。
- [ ] 重复凭据可确认另存；取消编辑、无效输入、保存失败及磁盘冲突不丢草稿。仅用测试副本验证损坏检测、备份恢复及异常原件保留。
- [ ] GUI 保持普通权限，仅核心请求 UAC；取消后无多余核心或网卡，配置保留，启动自动连接队列停止。
- [ ] 两套网络同时通信，独立断开、重连及应用参数；稍后应用保持旧连接，立即应用失败保留已保存内容和实际错误。
- [ ] 相同身份、TUN、手动地址或显式监听端口冲突得到明确反馈；网络 A 启动较慢时仍能查看并断开 B。
- [ ] 删除与连接／恢复并发时不留下孤立实例；保存并应用期间修改其他偏好不丢数据，写盘失败不重连。
- [ ] 重新加载不重复启动队列；磁盘记录被移除但仍运行的实例保留断开入口。

## 设备、迁移与邀请

- [ ] 核对实际节点、虚拟地址、直连／中转及可用质量；未知指标不显示假零，设备图标覆盖持久化且不重连。
- [ ] 双向传输观察速率与累计；对端断开累计不下降，多网络不串数据，重连只重置目标会话。缓存过期显示未知和曲线缺口，恢复不产生尖峰。
- [ ] 官方 TOML 导入、预览及导出使用真实系统对话框；取消或失败不误报成功，未展示字段保留，导出可由同版本官方客户端读取运行。
- [ ] 无效或不支持的配置列明原因、允许保留导出但阻止连接；验证节点名、IPv4、TUN、P2P、MTU、IPv6、Magic DNS 和 Windows 广播中继实际效果。UPnP／打洞按实际网络条件记录。
- [ ] 真实系统剪贴板和手动复制兜底可用；另一台 ClearTier 粘贴后核对、手动添加连接并通信，本机参数不被发送方覆盖。
- [ ] 待应用修改时分享运行参数，重连后才更新；停止时分享保存参数，未知状态拒绝生成。无效邀请、更换邀请、重复确认及保存重试不丢表单。

## 后台与异常

- [ ] 首次关闭说明、托盘打开／退出、关闭行为设置及重复启动正常；窗口反复隐藏打开不重连，托盘不可用时仍能操作窗口。
- [ ] 退出确认可取消；确认后 GUI、核心及临时网卡清理，无网络时直接清理退出。
- [ ] 登录启动默认关闭；启用后登录进入托盘，仅自动连接项尝试连接，取消 UAC 停止队列。关闭后不再登录启动，中文／空格路径及免安装固定路径正常。
- [ ] 临时节点或服务器不可达不反复重建网卡；仅结束 `--core-host` 工作进程后显示异常，需要提权时等待手动重连，无后台 UAC 或遗留 TUN。
- [ ] 有待应用修改时恢复沿用旧运行参数；主动断开、关闭恢复或退出后无迟到实例，重新开启恢复不启动已断开项。
- [ ] 重试预算与稳定后重置符合[恢复策略](architecture.md#核心进程权限与退出)，配置和资源错误停止重试。
- [ ] 睡眠唤醒、切换上网环境及持续后台使用后状态可同步，CPU／内存无持续异常增长，日志保持轮换。

## 诊断与安装

- [ ] 诊断摘要与日志目录正确；保存对话框取消不报成功，导出含版本、状态和错误码，不含凭据、实际地址、名称、用户目录、完整配置或邀请。
- [ ] NSIS 安装、升级保留配置及启动偏好；运行中安装先通知清理，未确认退出时中止替换。
- [ ] 卸载默认保留配置、清理进程和登录启动项，重装可读取；仅明确勾选才删除应用数据，不删除其他软件共用资源。

## 更新验收

- [ ] 安装首个包含更新器的版本，再发布更高的测试版本；Release 仅含 ZIP、NSIS 和内嵌签名的 latest.json，构建、上传校验完成后才发布。
- [ ] 启动延迟检查、托盘运行、24 小时间隔及重启后间隔有效；关闭自动检查后不再自动请求，手动检查可用，断网与限流不误报已是最新。
- [ ] 正式／预发布渠道与 SemVer 顺序正确；不降级、不重装相同版本，草稿和附件不完整版本不提示。
- [ ] 下载进度、取消及重试正常；篡改包、签名或签名版本阻止安装，下载时网络不断开。
- [ ] 有连接或启动中任务时只确认一次；取消不影响连接，清理失败不启动安装器；成功后 NSIS 升级重启并保留配置／偏好，按已有规则自动连接。
- [ ] 安装器启动失败保留旧程序操作入口；免安装版只下载 ZIP，不启动 NSIS，中文／空格安装路径识别正确。

## 核心分项检查

在仓库根目录，以普通权限 PowerShell 调用仓库中的检查脚本，`-AppDirectory` 指向完整免安装目录；以下使用本机构建目录为例。`Cancel` 在 UAC 中取消，`Tun` 在 UAC 中同意：

```powershell
$packageDirectory = (Resolve-Path .\artifacts\windows-x64\exe).Path
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-core.ps1 -AppDirectory $packageDirectory -Mode Process
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-core.ps1 -AppDirectory $packageDirectory -Mode Cancel
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-core.ps1 -AppDirectory $packageDirectory -Mode Tun
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-core.ps1 -AppDirectory $packageDirectory -Mode Recovery
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-core.ps1 -AppDirectory $packageDirectory -Mode MissingResource
```

`Direct` 为进程内基础检查。成功报告要求 `passed: true`、错误及清理错误为空；`Process` 验证不同控制端／核心 PID，`Tun` 验证双网卡创建及独立清理。`Recovery` 仅验证普通权限无 TUN 的独立进程恢复，不代替 GUI 自动恢复验收。检查不使用日常配置，`Tun` 使用临时测试网卡；报告及关联日志应一并保留。
