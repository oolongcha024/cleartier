# 仪表盘真实数据

阶段 4 接通桌面核心的本机节点名称、远端设备、隧道质量、字节累计与速率趋势。浏览器保留独立演示数据，不调用原生核心。当前完成本地自动化与浏览器通信回归，Windows 原生构建、真实 TUN 及两台设备传输仍待验收。

## 展示约定

- 连接卡片展示本机虚拟 IP、实际运行的节点名称及自动连接开关。已保存但尚未应用的名称不会冒充实际名称。
- 设备列表包含当前路由中全部远端设备，不包含本机，不保留离线设备历史。顺序按名称和 ID 固定，避免核心迭代顺序改变导致跳动。
- 基础列为设备、虚拟 IP、直连／中转、延迟、丢包率。点击设备名称按行展开协议、中转下一跳和核心版本，不新增页面或浮窗。
- 直连／中转及下一跳遵循实际运行的延迟优先策略。延迟与丢包来自核心选择的默认直连隧道；默认隧道暂不可用时选取稳定的可用连接。多条隧道的丢包率不相加。
- 核心丢包指标来自隧道探测，不等于游戏业务丢包。中转节点没有端到端测量值时显示 `—`，不使用下一跳质量代替；缺少 IP 的节点仍可展示，但无复制入口。图标只依据明确的公共服务器角色及本机手动偏好，普通节点默认使用通用设备图标。
- 查询失败保留设备及累计值，标记“数据暂未更新”，即时速率、延迟及丢包率显示 `—`。成功查询后恢复；不把一次查询失败当作主动断开。

## 设备图标

图标默认“自动”：核心 `Route.feature_flag.is_public_server` 为真时使用服务器图标，其他节点使用通用设备图标，不从名称、IP、版本或连接路径猜测操作系统。浏览器演示也通过相同规则选择图标，不再预设 Windows／Mac 图标。

直接点击设备行前的图标打开单选菜单，可选自动、电脑、笔记本、服务器、路由器和手机；设备名称及箭头独立控制连接详情展开。图标使用 48px 点击区域，菜单提供当前选中标记、悬停、键盘焦点、Escape 关闭及焦点返回。展开区域只保留三列连接信息。手动选择优先于默认映射；恢复自动会删除该覆盖记录。更改通过现有配置写入队列保存，成功后更新显示，失败时保留旧值和选择并展示存储错误；不触发核心连接或重连。

偏好存放在当前网络 `client.peerIcons`，键为对端路由提供的配置实例 UUID，值为设备类型。临时 peer ID、名称及 IP 改变时仍匹配原选择；不同本机网络配置的偏好独立，移除网络时一并移除。远端重建配置并获得新 UUID 时作为新节点处理。对端没有有效实例 UUID，或同一快照中多个远端节点使用同一实例 UUID 时，不提供手动选择，保留自动图标并给出原因。此键标识远端配置，不承诺识别复制配置背后的物理机器。

偏好只在客户端配置中保存，不放入核心参数、不向其他成员发送；浏览器预览仍只在内存中模拟选择。核心输出的公共服务器标记和唯一实例 UUID 经私有 IPC v4 传递。

## 统计口径与会话

统计当前网络在本机的隧道收发字节，包含核心通信和经本机转发的数据；不是整机互联网流量，也不等同于文件有效负载大小。实时速率使用 B/s、KiB/s、MiB/s 等二进制单位；累计使用 B、KiB、MiB、GiB 等。

每个实际实例启动生成新的会话 UUID，和可重复使用的配置 UUID 分开。一个节点内连接的重建不清空网络累计；目标网络重新启动才建立新会话，其他网络不受影响。停止后保留最后取得的累计快照，只在内存中保存，不提供跨会话历史或磁盘流量账本。

核心按连接 UUID 记录字节高水位并累加增量，补采 `PeerConnRemoved` 携带的最终计数。连接移出列表不扣减累计，重复事件／旧快照不重复累计，同一连接的回退计数不会产生负值；新连接 UUID 独立记账。关闭记录随会话释放。事件订阅发生已知丢失时标记统计可能不完整，不隐藏误差。统计是采样结果；强制结束核心或主动停止时，最后采样与实际停止之间的字节不保证全部取得，不作为计费依据。

字节以十进制字符串经过私有 IPC 和 Tauri 传递，前端使用 BigInt 求差后计算速率，避免超过 JavaScript 安全整数范围时丢失小额增量。格式化累计时才转换为展示数值。

## Module 与更新

| Module | 职责 |
| --- | --- |
| `cleartier-core/src/telemetry.rs` | 隧道计数、会话、设备字段及质量指标，过滤地址端点与密钥等无关信息 |
| `cleartier-core/src/status.rs` | 将实际核心信息及事件交给统计 Module，与连接状态一起形成快照 |
| `cleartier-core::connections::NetworkManager` | 携带统计快照，停止后保留最后的会话累计 |
| `features/networks/peer-icons.ts` | 自动角色映射、稳定偏好键及手动覆盖规则 |
| `features/networks/telemetry.ts` | 单独的前端订阅、速率、60 秒时间窗、过期及恢复；Interface 为 receive / stale / expire / remove |
| `features/networks/network-sessions.ts` | 在现有操作代次保护内分发快照，不让迟到响应污染新会话 |
| `features/dashboard/traffic-chart.ts` | 以真实时间定位曲线、共用双向刻度、缺失值分段 |
| `features/dashboard/use-dashboard-telemetry.ts` | 桌面数据与浏览器演示的展示适配 |

沿用每秒一次查询和焦点恢复刷新，查询不重叠。三秒未取得新数据标记过期；超过三秒的采样间隔不冒充瞬时速率，恢复后先建立基线再计算。图表保留最近 60 秒，缺失值留下缺口，零值保留为真实基线。

连接／配置状态与高频统计分开订阅。只变更字节或质量指标不会通知配置和连接 store 的订阅者，侧栏、编辑器、连接按钮不会被每秒采样整体重绘。本机节点名称另有窄订阅。私有核心 IPC 协议为 v4，控制端与核心随同一程序更新。

## 验证

`pnpm test` 包含精确差值、零／未知、超时与恢复、会话重建、多网络隔离、旧快照、时间窗、图表刻度和订阅隔离。Rust 测试覆盖最终计数、重复／回退、默认隧道、延迟优先中转、不伪造端到端质量及真实核心发现节点后的非零字节和协议信息。同进程核心可能自动采用 ring 隧道，测试以实际报告的协议为准，不强制声称为 TCP。

浏览器回归通过测试专用 Tauri Adapter，不打包进应用，也不创建实际网卡。使用 agent-browser 的独立会话，在打开页面之前加载 `tests/browser/fixtures/native-telemetry.js`，然后执行 `tests/browser/dashboard-telemetry.js`。覆盖基础丢包列、实际节点名、按行展开、过期保留、恢复、停止保留及新会话归零。普通预览继续覆盖即时切页及窄窗口布局。图标回归使用 `tests/browser/peer-icons.js`，覆盖角色默认、未展开时直接选择、图标与详情操作独立、恢复自动、保存失败和不触发核心操作；测试专用 Adapter 支持刷新后检查保存偏好。

Windows 实机验收：

1. 连接自有网络，另一台机器可使用官方客户端；核对节点名称、虚拟 IP、设备及实际直连／中转关系。
2. 双向传输文件，观察两个方向的速率和最近 60 秒曲线；累计量持续增长，协议开销会使其与文件大小不同。
3. 让对端断开或重连，当前网络累计不下降；中转设备未知的质量显示 `—`，不能显示虚假的零。
4. 同时连接另一网络，切换选择器显示各自数据；停止或重连一个网络，另一个累计保持独立。
5. 短暂查询失败时保留最后设备和累计，并明确标记；恢复后不出现跨缺口连线或瞬时速率尖峰。

本次不增加主动测速、端到端探测或自动调整 P2P 参数。
