# 官方 TOML 兼容与高级配置

阶段 5 使用固定的 EasyTier v2.6.4 核心完成配置迁移。网络配置页提供「导入 TOML」，每条记录提供导出按钮；不提供直接编辑 TOML 的界面。

## 导入与导出

- 桌面通过系统文件对话框选择 UTF-8 TOML，支持 BOM，文件上限 256 KiB。取消选择不创建记录，无效语法或超限不进入保存流程。
- 预览显示网络、节点、地址和服务器，密钥只显示是否包含；支持修改本地名称及 TUN 名称。原有节点名称、静态地址、监听端口和其他显式配置保持不变。
- 新记录分配独立 UUID，默认手动连接，不覆盖已有配置。未指定 TUN 名称时，在 Windows／Linux 填入独立默认名称；已有名称冲突需明确修改。相同网络凭据可另存，同时运行仍受阶段 3 的互斥规则约束。
- 未展示但当前核心支持的字段在连接时实际生效。未知字段、无效类型、暂不能处理的组合和平台选项列出字段路径与原因；允许保留和导出，连接前再次拒绝，且不停止已有会话。
- 导出使用已保存配置，包含密钥和本机参数，供官方客户端迁移，不作为朋友加入网络的邀请。客户端备注、图标、自动连接及设备图标偏好不进入 TOML；已有运行会话不影响导出的已保存版本。
- 保存位置由系统对话框选择，取消或失败不显示导出成功；通过同目录临时文件原子替换。解析错误不向界面或日志输出原文、字段值或凭据。

保留的是配置字段与含义，不保证注释、空白、键顺序或原文件排版。文件路径、日志及外部配置来源字段保留供迁移，但目前不交给提权核心运行，也不自动读取或复制其指向的文件。

## 转换与存储

`cleartier-core::configuration` 是 TOML 兼容 Module，其 Interface 是 `import / inspect / export`。导入通过固定核心校验，先检查 flags 类型，防止上游对非法类型的 unwrap；再用官方类型往返比对发现被忽略的根字段、嵌套字段与数组字段。预览和真正启动共用相同校验。

原始 TOML 保存在 `ConnectionConfig.officialToml`。这是可选的 v1 已知字段；既有配置继续有效。存储允许保留已解析但暂不能运行的导入内容，继续使用原子替换、备份和修订检查。实际连接仍需要通过核心校验。

有效 TOML 从保留底稿生成，仅覆盖与导入投影不同的表单字段，并使用本地记录的实例 UUID。未改动的显式默认值、缺省字段、监听列表、路由、子网代理、STUN、其他 flags 等保留。编辑服务器列表时，地址未变的条目保留其公钥等属性。改动某字段代表有意替换该字段；删除服务器不会保留被删除条目的属性。

Tauri 的 `toml_import / toml_inspect / toml_export` 隐藏文件选择和普通用户文件访问。React 通过 `platform/official-configuration.ts` 使用这个 Interface，导入走现有串行持久化队列。浏览器预览继续独立运行，文件操作明确提示需要桌面环境；浏览器回归以模拟原生通信覆盖对话框流程，不将模拟结果当作真实解析或文件系统验收。

## 已核对的高级参数

| 表单 | 核心字段及行为 |
| --- | --- |
| 节点名称 | `hostname`；留空跟随系统，核心会清理控制字符并截取 32 字符，导入此类值时提示修改 |
| IPv4 | `dhcp / ipv4`；自动、手动与不分配分别表达；固定核心将 `/32` 按 `/24` 处理，因此提示确认并修改前缀 |
| TUN | `flags.dev_name`；本地独立默认名，Windows 查实际适配器名称，Unix 使用系统接口查询；macOS 按系统分配名称，导入显式名称需处理平台提示 |
| MTU | `flags.mtu`；留空使用 1380，启用加密后实际网卡再减 20；沿用官方 GUI 的 400–1380 输入范围，超出范围的导入值保留但阻止连接 |
| IPv6 连接 | `flags.enable_ipv6`；本机新配置同步设置 IPv6 动态监听；导入配置保留其监听列表；虚拟 IPv6 地址属于另外的配置字段 |
| P2P | `disable_p2p / lazy_p2p / p2p_only`；自动、按需、关闭自动、仅直连；“关闭自动”保留上游对声明需要 P2P 节点的例外，不承诺强制中转 |
| 延迟优先 | `latency_first`；按时延选路，不代表按丢包或 QoS 选路；仅直连模式下不启用 |
| TCP／UDP 打洞、UPnP | 对应 `disable_*` 的反向映射；启用代表允许尝试，不保证打洞或映射成功 |
| Magic DNS | `accept_dns / tld_dns_zone`；修改后缀时补齐末尾点；未修改的导入后缀保持原样 |
| UDP 广播中继 | `enable_udp_broadcast_relay`；仅 Windows，沿用提权核心及既有运行资源 |

新建配置继续使用动态 TCP／UDP 监听端口避免争用；导入显式监听参数不自动改成动态端口。连接参数保存与立即／稍后应用的规则不变，其他网络继续运行。

## 验证与实机验收

本地检查覆盖 TOML 往返、未展示设置、未知嵌套字段、非法 flags 类型、组合／平台限制、无服务器配置、错误脱敏、存储重开，以及经真实核心工作进程运行导入配置。浏览器覆盖选择取消、格式错误、密钥遮罩、TUN 冲突、保存失败重试、独立记录、编辑保留和导出取消／失败。

Windows 新产物仍需验收：

1. 从官方客户端导出一份测试配置，导入并核对本机参数、默认手动连接及独立记录；取消、无效文件与保存失败不丢输入。
2. 导入明确的监听、路由或子网配置，修改可视化字段并导出，用官方同版本客户端读取，核对其余配置仍在且能运行。注释与排版可以变化。
3. 在测试副本加入未知字段、错误类型或跨平台字段，确认问题列表完整、可以保存导出、连接被拒绝；重新导入有效副本后可运行。
4. 在真实双网络上验证 TUN 名称、静态地址及监听端口冲突；修改一个网络不会中断另一个。
5. 使用两台测试设备检查 P2P、仅直连、IPv6、MTU、Magic DNS 与 Windows 广播中继的实际行为。UPnP／打洞效果取决于真实路由器与网络条件。

容器编译、无 TUN 核心检查和模拟原生通信均不能替代这些实机项目。
